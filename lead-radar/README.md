# Lead radar

Слушает Telegram-чаты, где вы состоите, ищет по всей публичной части Telegram
и присылает сообщения, похожие на запрос клиента.

Тем две, и каждая уходит **в свою группу**:

| Тема | Что ищет | Куда шлёт |
|---|---|---|
| Недвижимость | «ищу квартиру в Батуми», «стоит ли брать в Дубае в рассрочку» | `TELEGRAM_CHAT_ID` |
| Тёплый контакт | «переезжаем в Ереван, оформляем ВНЖ» — купит через 3–12 месяцев | `TELEGRAM_CHAT_ID_WARM` |

Разные группы — не украшение: тёплый контакт это ещё не заявка, и в чате
отдела продаж он бы только мешал отличать одно от другого. Если
`TELEGRAM_CHAT_ID_WARM` не задан, тема просто выключена, и в группу
недвижимости из неё не попадает ничего.

Была ещё третья тема — заказы на разработку. Её убрали: за две недели она
дала под полторы сотни срабатываний в сутки и ни одного заказа, а половину
заходов глобального поиска забирала себе. Если понадобится вернуть —
`git log` помнит, тема снималась целиком одним коммитом.

Отвечаете вы сами, руками. Скрипт никому не пишет — он только находит.

## Запуск (10 минут)

```bash
cd lead-radar
npm install
cp .env.example .env
```

1. **api_id и api_hash** — https://my.telegram.org → API development tools →
   создать приложение. Впишите в `.env`.
2. **Вход в аккаунт** — `npm run login`, введите телефон и код из Telegram.
   Скрипт напечатает строку сессии — вставьте её в `.env` как `TG_SESSION`.
3. **Куда слать находки** — `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`
   возьмите из `.env.local` в корне проекта (тот же бот, что шлёт заявки с сайта).
4. **Вторая тема (необязательно)** — создайте ещё одну группу, добавьте туда
   того же бота, напишите в неё что угодно и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Значение `chat.id`
   впишите в `.env` как `TELEGRAM_CHAT_ID_WARM`.
5. **Запуск** — `npm start`. В каждую подключённую группу придёт
   «🟢 Lead radar запущен. Тема: …» — так сразу видно, что канал не перепутан.

Чтобы работал круглосуточно — держите запущенным на сервере
(`pm2 start index.js --name lead-radar` или systemd-сервис).

## Где брать чаты

Скрипт видит только те чаты, в которых состоит ваш аккаунт. Сначала вступите:

- Чаты релокантов и экспатов: Ереван, Тбилиси, Батуми, Дубай
- Чаты по недвижимости и аренде в этих городах
- Чаты «Русские в ОАЭ / Армении / Грузии», IT-релокация, бизнес-нетворкинг
- Для темы разработки — чаты фриланса и заказов: там заказчики пишут сами.
  В чатах про недвижимость заказы на сайты почти не встречаются, поэтому
  для второй темы основной источник — глобальный поиск, а не подписки.

Искать: поиск по Telegram, а также TGStat и Telemetr — по ключевым словам
и по городам.

Пока чатов мало, оставьте `TG_WATCH_CHATS` пустым — слушать будет все.
Когда станет шумно, впишите туда 10–20 лучших чатов через запятую.

## Сколько чатов держать

Telegram разрешает аккаунту состоять в 500 группах и каналах (1000 с Premium),
но упрётесь вы не в этот предел, а в собственное внимание: сорок чатов дают
около 6000 прочитанных сообщений и под две сотни уведомлений в сутки. Вдвое
больше чатов — вдвое больше уведомлений, и в какой-то момент их перестают
читать вовсе. Разумный потолок — 60–80 чатов, и только отобранных по сводке.

Вступать лучше по 10–15 чатов в день и руками из приложения, а не через API:
быстрые массовые вступления Telegram считает поведением скрапера и наказывает
не предупреждением, а ограничением аккаунта. Аккаунт у радара один, и на нём
держится всё.

## Сводка по чатам и кнопки оценки

Под каждой находкой две кнопки — «✅ Живой» и «❌ Мусор». Нажатие записывается
в `chat-stats.json` вместе с чатом, откуда пришла находка, и кнопки заменяются
отметкой о выборе, чтобы один лид не накрутил счётчик дважды.

Раз в сутки (`REPORT_HOUR`, по UTC) в каждый канал приходит сводка по своей
теме: сколько сообщений прочитано в каждом чате, сколько раз сработали
словари, сколько находок отправлено и как вы их оценили. Отдельными разделами
идут чаты, где много говорят, но ничего не подходит, и чаты, промолчавшие
сутки, — первые кандидаты на замену.

Чаты в сводке отсортированы **по вашим ✅, а не по числу находок**. Это
намеренно: чат с одним живым контактом полезнее чата с тридцатью
срабатываниями словаря, на которые никто не ответил. Правило закреплено
тестом `npm run test-stats` — если однажды переписать сортировку на более
очевидную, по объёму, сводка перестанет отвечать на вопрос, ради которого
её завели.

Оценки за всё время переживают суточное обнуление, поэтому чат, показавший
себя на прошлой неделе, не падает вниз из-за тихого дня.

## Настройка словарей

Правило у каждой темы своё, потому что ошибаются они по-разному.

**Недвижимость** — `keywords.js`. Лид, если есть **гео + тема + намерение**
и нет стоп-слов. Главная ловушка — арендатор вместо покупателя, поэтому
аренда отсекается, пока в тексте нет признака покупки.

Русский, армянская графика и армянская латиница («pntrum em bnakaran») —
в одних и тех же списках. С латиницей есть тонкость: язык агглютинативный,
суффиксы липнут к корню, поэтому у регулярок есть открывающая граница слова
и НЕТ закрывающей — иначе «Erevanum» не совпадёт с «erevan». Исключение —
трёхбуквенные слова вроде «tun»: там закрывающая граница обязательна, иначе
оно ловит «fortune» и «tuning».

**Тёплый контакт** — `keywordsWarm.js`. Это единственная тема, где находка
заведомо НЕ лид: человек переезжает или оформляет статус, жильё ему
понадобится через 3–12 месяцев, и прямо сейчас за него никто не борется.
Правило: страна + переезд или статус + признак того, что это надолго
(семья, бизнес, ВНЖ). Одного «переезжаю в Ереван» мало — так пишет половина
чата релокантов. Писать такому человеку «подберём вам квартиру» нельзя:
на этом этапе это спам. Только польза — ответ на его вопрос, ориентир по
ценам, предупреждение о подводном камне.

- Приходит мусор → добавьте слово в `STOP` соответствующего файла
- Пропускает нужное → добавьте в `TOPIC`/`INTENT`
- В уведомлении видно, какие слова сработали — по ним и подкручивайте

Классификатор на модели — необязательная надстройка, и сейчас он выключен:
без `ANTHROPIC_API_KEY` радар судит только по словарям, как и задумывался.
Единственный регулятор строгости в этом режиме — `ALERT_MIN_SCORE` в `.env`:
4 по умолчанию, 5–6 оставит только явные запросы с бюджетом или прямым
«хочу купить».

После любой правки: `npm run test-words` — прогон на образцах, включая
подстрочные ловушки («бот» внутри «работа», «api» внутри «капитал»).
И `npm run test-real` — те же словари на настоящих сообщениях, вычитанных
из группы находок. Второй тест важнее: выдуманные примеры проверяют то, что
мы и так предусмотрели, а эти — то, на чём фильтр ошибался в бою.
Ключ к модели для обоих не нужен. Если есть `ANTHROPIC_API_KEY` —
`npm run test-ai` проверит ещё и вердикты модели по обеим темам.

Первую неделю проверяйте находки каждый день и правьте словари: настроенный
радар даёт несколько живых запросов в день, ненастроенный — сотню мусорных.

## Добавить третью тему

Всё описание тем — в `profiles.js`: словарь, поисковые фразы, название и
свой чат. Движок про темы ничего не знает, поэтому новая тема — это один
объект в списке плюс промпт в `classifier.js`.

## Как отвечать, чтобы это работало

- Отвечать **в чате**, по делу, без ссылки в первом сообщении. Сначала польза —
  конкретный ответ на конкретный вопрос.
- В личку — только если человек сам попросил или разрешил.
- Профиль аккаунта должен быть говорящим: имя, «недвижимость Дубай/Ереван/
  Грузия», ссылка на сайт. Тогда заинтересовавшиеся приходят сами.
- Читайте правила чата. В большинстве чатов реклама запрещена, а полезные
  ответы — нет.

Массовые рассылки в личку и ссылки в каждом сообщении дают обратный эффект:
бан аккаунта, исключение из чатов и испорченная репутация в комьюнити,
которое и есть ваш рынок.
